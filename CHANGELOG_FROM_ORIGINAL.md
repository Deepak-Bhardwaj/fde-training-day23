# Changelog From Original Maritime Case

The original case had a strong FDE discovery sequence and useful maritime constraints but did not explicitly teach the architecture shown in the supplied reference visuals. This rebuild makes that architecture the participant backbone.

## Material changes

- Replaced the generic discovery-led eight stages with eight **architecture-native** stages.
- Added explicit semantic layer, ontology, canonical identifiers and entity resolution.
- Added a temporal/provenance knowledge-graph design challenge and graph-platform ADR.
- Added structured + graph + vector + policy + controlled-memory hybrid retrieval.
- Added runtime context-graph construction with actor, time, connectivity, freshness, policy and conflict state.
- Added bounded AI/agent orchestration with deterministic safety/authority controls.
- Strengthened offline edge continuity, duplicate replay and reconnect reconciliation.
- Added concrete prompt-injection, stale/missing source, identity conflict, clock drift, superseded-policy and AI-outage traps.
- Replaced placeholder golden-scenario expected behaviors with 15 deterministic adjudicated scenarios.
- Added heterogeneous vessel/shore/external evidence instead of relying on one historical CSV.
- Preserved the source benchmark separately from the 140-row fixture profile to avoid false statistical reconciliation.
- Removed mandatory Qwen/Qwen-Coder dependency; core path is architecture → PRD → Google AI Build → verification.
- Added 15 participant templates, app screen/acceptance requirements, build prompt, consolidated fixture bundle, manifest and automated QA.
- Reframed decision tracing to observable evidence and concise rationale rather than hidden chain-of-thought.
